## Reproduce the exact scored CSV from raw data

Use Python 3.11 and install the pinned dependencies. Obtain and unpack the five official competition CSVs yourself; preserve their original names.

```sh
python3 -m venv .venv
source .venv/bin/activate
python -m pip install -r opencode_run/requirements.txt
python -B reproduce_final.py --data-dir /absolute/path/to/sweettv-tv-program-recommender
```

The `reproduce_final.py` wrapper was added by Codex during report preparation. It imports the original OpenCode modules, rebuilds full-history interval coverage, refits the frozen strategy, checks all 1,260 template users and 6,632 candidates, and requires the reproduced CSV's hash to match the scored file. It refuses to overwrite an existing output. Its raw-data reproduction was actually tested; see [report_audit/clean_reproduction.json](report_audit/clean_reproduction.json). This packaging work is outside the original OpenCode export and is disclosed separately.

For cached reruns, use `--reuse-preprocessing` only with the `--cache-dir` created by a successful first run. The cache and output are ignored by Git.

## Method and evaluation

Views and schedules join on channel and half-open interval overlap. Union observed fragments within each airing; do not count gaps or overlapping logs twice. Ignore `tv_show_id=0` as an item. Labels require at least 80% of the original airing duration; repeat features use at least 50%. Airings crossing the training cutoff cannot contribute incomplete labels. Candidate programmes start inside the target period and can cross its end. Repeats are allowed.

Frozen score: `0.9 * (0.7 * R + 0.3 * A) + 0.1 * E`. R is the schedule-adjusted personal repeat count; A is the original >=80% co-view association-rule score; E is schedule-adjusted log-count EASE (lambda=1000). Independently max-normalize each component over eligible candidates. Apply schedule adjustment before normalization; do not additionally normalize the R/A blend. EASE keeps negative coefficients until complete prediction, then clips negative predicted scores. Fallback and exact-score ties use training >=80% distinct-user popularity, qualifying-airing counts, then numeric ID. No time decay or future viewing is used.

Schedule factor: `sqrt(clip((target_airings/target_weeks)/(past_airings/train_weeks), 0.25, 4))`. Count owned, positive-duration, labelled and deterministically deduplicated airings. Missing personal evidence stays zero; positive learned evidence without historical schedule opportunities is an inconsistency.

All-model common holdout: train 9 March-18 May; validate 18 May-27 July 2020; 1,260 template users and 6,361 candidates. Labels are the five most frequent qualifying programmes (ascending numeric ID on ties); AP@5 is zero for no-positive users. Final hybrid MAP@5: **0.392665** (all users), **0.399643** (1,238 positive users), **0.414461** (1,150 users with five positives).

A second overlapping retrospective backtest trains 9 March-4 May and validates 4 May-27 July (12 weeks; 7,039 candidates), MAP@5 **0.412063**. Final refit uses 9 March-27 July (20 weeks) and predicts 27 July-19 October (12 weeks). Repeated historical selection and paired bootstrap intervals are descriptive, selection-unadjusted evidence; these are not independent test sets.

Required families implemented: content-based filtering and association rules. EASE, repeat and popularity are additional comparators. No matrix-factorization claim is made for EASE. Exact final component-only MAP@5 and both users' ordered IDs/titles/categories are in [report_audit/report_data.json](report_audit/report_data.json).
